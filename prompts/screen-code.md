# Internal Prompt — Screen Code Generation

> The agent uses this template internally during **Phase 3 — CODE**. Generates a single React + Tailwind screen file.

## Inputs

- Locked `design-tokens.json`
- Locked `design-dna.md`
- Approved `asset-manifest.json` (icons + images)
- Screen spec file from `templates/screen-spec.md` filled in for this screen
- The screen's reference image (for layout cues only, NOT for color/type)
- The screen's reference prompt (if any)
- `tailwind.config.ts` or `app/globals.css` with the token theme applied

## Procedure

### Step 0 — Verify prerequisites

- [ ] `design-tokens.json` exists and validates against the template schema
- [ ] Token classes resolve in Tailwind (run a quick test: render a `<div className="bg-bg-base">` and confirm)
- [ ] All icons in screen spec exist in `icon-library/lucide-icons.json`
- [ ] All images in screen spec exist on disk at their manifest paths
- [ ] shadcn/ui is installed and the required primitives are present (`Button`, `Card`, `Input`, etc.)

If any check fails, STOP and fix it before generating code.

### Step 1 — File header

Every generated screen starts with:

```tsx
/**
 * <Screen ID> — <one-line description>
 *
 * Generated by ui-from-references skill.
 * Tokens: ../design-tokens.json (v<version>)
 * Assets: ../asset-manifest.json (v<version>)
 * Reference: <path to reference png>
 *
 * Anti-patterns to AVOID in this file:
 *  - inline hex codes (use Tailwind token classes)
 *  - emoji icons (use Lucide)
 *  - arbitrary Tailwind values (no bg-[#xxx])
 *  - default Tailwind colors (gray-500, blue-500, etc.)
 */
```

### Step 2 — Imports

Order strictly:

1. `react` and framework
2. Icons from `lucide-react` (alphabetical)
3. shadcn UI primitives (alphabetical)
4. Local components
5. Asset imports from `public/assets/...`
6. Types

Example:

```tsx
import { ChevronLeft, Gift, Home, LayoutGrid, Menu, Search, User, Wallet } from "lucide-react";

import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";

import { Chip } from "@/components/chip";

import mahjongWays from "@/public/assets/game/mahjong-ways.png";
import luckyNeko from "@/public/assets/game/lucky-neko.png";

import type { ScreenData } from "@/types/screen";
```

### Step 3 — Composition

Build the screen TOP-DOWN, one section per JSX block, matching the screen spec's composition table.

Each section MUST be a clearly named component or a commented region:

```tsx
return (
  <div className="min-h-screen bg-bg-base text-text-primary font-body">
    {/* Header */}
    <header className="h-13 px-4 flex items-center justify-between">
      <button aria-label="Back">
        <ChevronLeft className="size-5 text-text-primary" />
      </button>
      <h1 className="text-title font-bold">เกมทั้งหมด</h1>
      <div className="flex items-center gap-3">
        <Search className="size-5 text-text-primary" />
        <LayoutGrid className="size-5 text-text-primary" />
      </div>
    </header>

    {/* GameType filter */}
    <div className="px-4 py-2 flex gap-2 overflow-x-auto">
      <Chip active>สล็อต</Chip>
      <Chip>คาสิโนสด</Chip>
      <Chip>โป๊กเกอร์</Chip>
      <Chip>กีฬา</Chip>
      <Chip>ยิงปลา</Chip>
    </div>

    {/* ... continue per spec ... */}

    {/* Bottom nav */}
    <BottomNav active="none" />
  </div>
);
```

### Step 4 — Token discipline

Every class MUST resolve to a token. Quick audit before saving:

```bash
# Run from project root after writing the file
grep -nE 'bg-\[|text-\[|border-\[|rounded-\[' app/<screen>.tsx
# If any output → fix those occurrences before finalizing
```

Forbidden class patterns:
- `bg-gray-*`, `bg-zinc-*`, `bg-slate-*` — use `bg-bg-*` tokens
- `text-white`, `text-black` — use `text-text-primary` / `text-text-inverse`
- `rounded-lg`, `rounded-xl` — use `rounded-card` / `rounded-md`
- `bg-[#xxx]`, `text-[#xxx]` — use named tokens

### Step 5 — Type safety

- Data passed to the screen MUST be typed against `ScreenData` from the screen spec
- No `any`, no `as unknown as`
- Use discriminated unions for state (`{ status: 'loading' } | { status: 'ready', data: ... }`)

### Step 6 — Accessibility minimum

- Every interactive element has either visible text OR `aria-label`
- Every image has `alt` (even decorative — use `alt=""`)
- Color contrast ≥ 4.5:1 for body text against background (verify with WebAIM if uncertain)
- Focus order matches visual order
- ESC closes any modal/sheet opened from the screen

### Step 7 — Mobile-first sizing

- Container at the screen viewport: `max-w-[<viewport.width>px] mx-auto` for desktop preview
- Use Tailwind spacing scale only (no arbitrary `px-[17px]`)
- Bottom nav is `fixed bottom-0 inset-x-0` with content `pb-22` to compensate
- Use `svh`/`dvh` units for full-height layouts if needed

### Step 8 — Save and snapshot

1. Save `app/<screen-id>.tsx`
2. If shadcn primitives are new, generate them: `npx shadcn@latest add <component>`
3. Move to Phase 4 (Verify)

## Failure modes to avoid

- **Premature optimization**: don't extract sub-components unless they're reused. One screen = one file is fine for first pass.
- **Inline data**: keep the static game list etc. at the top of the file as a `const`, NOT inline in JSX. Easier to swap for a real fetch later.
- **Implicit color choices**: if you find yourself wanting a color not in tokens, STOP and either pick the closest existing token OR go back to Phase 1 and add the missing token.
- **Skipping the icon library check**: never use `<svg>` inline. If Lucide doesn't have it, add a real entry to `icon-library/lucide-icons.json` first.
